# Эксперимент: уведомления DSH через LAN Relay

Это тестовый компонент, не готовая миграция команды. Команда сообщила об успешном сквозном тесте на двух ПК; устойчивость работы и повторные запуски требуют дальнейшей проверки. Используйте тестовый ящик и по возможности отдельный тестовый профиль. Дополнительная информация о сервере и тестовых сертификатах — в `experiments/LAN_PILOT.md`.

## Получение и обновление кода

Получите код из публичного репозитория; после публикации проверенных обновлений его можно обновлять через Git:

```powershell
git clone https://github.com/Akyltist/Hardline-Relay.git
cd Hardline-Relay
git pull --ff-only
```

Для следующих обновлений выполните `git pull --ff-only` из папки репозитория. Если Git сообщает о локальных изменениях или расходящихся ветках, разберите причину, не удаляя изменения. Экспериментальные изменения доступны только после их публикации. Используйте согласованную версию.

Скопируйте каталог `experiments/dsh_plugin/lan-receiver` из репозитория в отдельную локальную папку тестового профиля и настраивайте только копию. Секреты и настройки не храните в Git. После `git pull` обновляйте исходники локальной копии, сохранив свою конфигурацию и секреты; перед обновлением остановите тестовый клиент и приёмник.

## Настройка тестового профиля

1. Получите отдельно выданные для этого ящика тестовые TLS-сертификат, закрытый ключ, токен Relay и `client.json`. Храните их в защищённой папке вне репозитория с доступом только нужной учётной записи. У сертификатов ограничен срок действия.
2. Установите зависимости Python проекта в отдельное окружение. Подключите `experiments/windows_lan_pilot_client.ps1` как отдельный тестовый MCP-клиент; он принимает `RepoRoot`, `CredentialDirectory`, `PythonPath`, `ServerPort`. Укажите локальные пути этого ПК. Ключи и токены не передаются аргументами командной строки.
3. Подключите скопированный `lan-receiver` как bundle по правилам конкретной установки DSH, в отдельном тестовом профиле. Сам Git clone плагин не устанавливает; совместимость с конкретной версией DSH необходимо проверить.
4. Запустите тестовый профиль и откройте нужный тестовый чат: до его создания идентификатора этой сессии может ещё не быть. В локальной копии `cordis.patch.yml` задайте свободный локальный порт, путь к отдельному закрытому файлу токена уведомлений и **точный sessionId тестового чата**. Берите идентификатор только из надёжного доступного контекста DSH для нужного чата. Переменная `$env:DSH_SESSION_ID` во внешнем терминале может отсутствовать и сама по себе не доказывает идентичность чата. Если надёжно получить ID не удалось, не включайте приёмник. Автоматический выбор другой сессии запрещён.
5. Создайте отдельный токен из 32 криптографически случайных байтов в виде 64 строчных шестнадцатеричных символов. Сохраните его в приватном файле с ограниченными правами. Он используется только для связи на этом ПК и отличается от токена Relay. Не выводите значения в чат, логи, Git или командную строку.
6. Для процесса MCP задайте `HARDLINE_PILOT_DSH_WAKE_URL` вида `http://127.0.0.1:<порт>/notice` и `HARDLINE_PILOT_DSH_WAKE_TOKEN` из того же защищённого файла. Например, в закрытом локальном сценарии PowerShell используйте присваивание `$env:HARDLINE_PILOT_DSH_WAKE_TOKEN = (Get-Content -LiteralPath $tokenFile -Raw).Trim()` без вывода значения. Переменные должны быть доступны именно процессу MCP при запуске. Адрес своего ящика клиент берёт из защищённого `client.json`.
7. В `noticeText` укажите свой тестовый адрес и имя MCP-клиента. Письма читайте через `inbox(agent=..., auto_ack=false)` с продолжением по `after_id` при `more=true`; подтверждайте `ack` только после обработки. Уведомление не содержит текста письма.

После запуска проверьте письмо между тестовыми участниками, адрес и фактическое пробуждение именно закреплённого чата. Проверьте отказ при отсутствии сессии, повторные письма и перезапуск. Локальный ответ HTTP 202 означает лишь успешный возврат `followup`, а не прочтение или подтверждение письма. Таймаут, сбой или перезапуск могут привести к повторному уведомлению; подтверждение получения проверяют отдельно. При ошибке сообщайте только её общую суть, без секретов.

## Тестирование с рабочим профилем

Для испытаний предпочтителен отдельный профиль и тестовый чат. Приёмник может разбудить только сессию, загруженную в том экземпляре DSH, где он работает. Если проверяется уже существующий чат в рабочем профиле, временное включение тестового приёмника требует согласования с владельцем этого профиля. Настройте loopback, точный `sessionId` и отдельный защищённый токен, как описано выше. После испытания штатно отключите только тестовый bundle и убедитесь, что его приёмник остановился. Компонент экспериментальный и не предназначен для постоянной работы без дополнительной проверки.

## Результат пилотного испытания

По отчёту участников, 26 ноября 2026 года письмо между двумя ПК вызвало пробуждение закреплённого чата DSH; чат прочитал письмо через `inbox(auto_ack=false)` и подтвердил его через `ack`. Локальный ответ `202` проверялся отдельно и не считался подтверждением прочтения. Клиент соответствовал ревизии `0b1e65d`, публичный пакет — `101ca96`. В другом наблюдении участник сообщил о повторном уведомлении без новой записи в журнале приёмника; причина требует выяснения. Эти результаты не гарантируют работу во всех установках DSH.

## Диагностика и завершение теста

- В одной проверенной установке DSH переустановка bundle не остановила предыдущий приёмник: он продолжал занимать порт и отвечать со старым конфигом. При `listen-error` проверьте, какой процесс слушает порт, и по возможности корректно остановите только свой тестовый приёмник. Если DSH не выгрузил его, перезапуск соответствующего экземпляра DSH может освободить порт; заранее учитывайте открытые задачи. Альтернатива для теста — другой свободный локальный порт, одинаковый в конфиге приёмника и `HARDLINE_PILOT_DSH_WAKE_URL`.
- Переустановка MCP в той же установке оставила несколько процессов клиента. Если вы видите `409` при занятом адресе, проверьте список процессов и их командные строки, не выводя секреты. Остановите штатным способом только проверенные лишние процессы своего тестового клиента; не трогайте чужие или неизвестные процессы. После отключения прежней сессии срок её аренды может сохраняться до 60 секунд.
- При включённом цикле уведомлений действующий клиент периодически продлевает аренду своего адреса. Отдельный клиент, пытающийся одновременно занять тот же адрес, может получить `409`; используйте уже работающий MCP-клиент для чтения и отправки. Не обходите проверку аренды.
- Запись `no-session` у приёмника и ответ `409` могут означать как закрытую или не загруженную сессию, так и неверно указанный `sessionId`. Проверьте оба варианта, прежде чем менять конфигурацию.
- Если приёмник настроен для автозапуска в тестовом профиле, он может запускаться вместе с DSH. После испытания отключите его штатным способом в этом профиле и проверьте, что именно ваш тестовый приёмник остановился. Сохраните данные и конфигурацию, которые ещё нужны для работы.
